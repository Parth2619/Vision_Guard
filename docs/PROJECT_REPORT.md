# VisionGuard Medical — Project Report

**Research prototype that audits AI-generated chest X-ray reports for unsupported or hallucinated claims.** Not clinically validated. Not for diagnostic use.

---

## 1. Problem statement

Vision-Language Models (VLMs) such as LLaVA-Med, Qwen-VL, and MedPaLM can generate free-text radiology reports from medical images. These reports can contain **hallucinated** claims — statements that are not supported by, or that contradict, the underlying image.

**VisionGuard Medical** is an agentic AI pipeline that:

1. Takes a chest X-ray and a report (either human-written, generated by a VLM, or the system's own VLM output).
2. Extracts each atomic medical claim from the report.
3. Retrieves independent visual evidence from the image using pretrained vision models.
4. Verifies each claim against the evidence.
5. Assigns one of three statuses — `supported`, `contradicted`, or `indeterminate`.
6. Flags high-risk uncertainty for human review.

The system is **conservative by design**: missing evidence is `indeterminate`, never `contradicted`; agreement with the source report alone is not treated as clinical truth; weak signals (classifier probability, detector score) are only promoted to a verdict when they are confident.

## 2. Architecture — mapped to the project diagram

The 8-stage architecture from the project brief:

| # | Diagram stage | Implementation |
|---|---|---|
| 1 | **Input** (medical image + VLM output) | `/audit` multipart endpoint; `models/vlm.py` generates the report-under-audit when `mode=vlm_from_image` |
| 2 | **Claim extraction** (LLM-based structured parsing) | `medical/extract.py` — rule-based typed extractor (OBJECT / ATTRIBUTE / COUNT / SPATIAL) implementing the `ClaimExtractor` protocol |
| 3 | **Independent visual evidence** | `models/xray.py` — torchxrayvision classifier (18 pathology labels); `models/detector.py` — Grounding-DINO zero-shot object detector + bounding boxes |
| 4 | **Claim-specific verification** | `medical/verify.py` — polarity-aware verdict rules per claim |
| 5 | **Fusion & calibration** | `models/calibration.py` — MLP (128→64→3) producing `calibrated_confidence` + 3-way probabilities |
| 6 | **Risk-aware decision gate** | `medical/risk.py` + `node_human_review` in `graph/build.py` — escalates on blockers, INDETERMINATE, or high-risk/low-confidence |
| 7 | **Human-in-the-loop review** | `api/review.py` SQLite persistence; Streamlit "Expert Review" tab with confirm/reject/insufficient buttons |
| 8 | **Final audited report** | `AuditReport` pydantic schema (per-claim verdict + evidence + bbox + confidence + risk + trace + overall status + timestamp + JSON export) |

The orchestration is a real **LangGraph `StateGraph`** with typed state, conditional edges, bounded retry (`MAX_RECHECKS = 1`), and a sanitized execution trace exposed to the UI.

```
START → validate → extract → evidence → verify → calibrate
                                                     ↓
                     recheck (max 1) ←── critic ───┐
                            ↓                      ↓
                        evidence  ←─ (if blockers) │
                                                   ↓
                                       risk_gate_human_review → END
```

### Phase 3 — Agentic framework (first working end-to-end)
- Typed schemas in `medical/claims.py`: `Claim`, `Evidence`, `ClaimVerdict`, `CriticFinding`, `TraceEntry`, `AuditReport`, `AuditRequest` with Polarity / Status / Provenance / ClaimType enums.
- Rule-based claim extractor (sentence splitting, section parsing, negation + uncertainty detection, finding + anatomy vocab).
- Evidence providers: `report_text_evidence` (T0), `synthetic_evidence` (demo KB with 4 rows).
- Verification rules: missing evidence → `indeterminate`; T0 alone insufficient; only independent evidence (T3 / synthetic / later IMAGE_MODEL) can promote to supported/contradicted.
- LangGraph `StateGraph` with 7 nodes and a conditional recheck loop bounded by `MAX_RECHECKS = 1`.
- FastAPI `/audit` + CORS to localhost Streamlit origins.
- Streamlit "Audit Workspace" (overview + inputs + verdicts + evidence + trace + JSON download).
- Non-agentic `baselines/text_only.py` comparator (all indeterminate).

### Phase 4 — Image evidence
- `models/xray.py` — lazy `TorchXRayVisionBackend` wrapping `densenet121-res224-all` (CPU). Pluggable `set_backend` / `get_backend` so tests use stubs.
- `FINDING_TO_LABEL` map between our extractor vocab and torchxrayvision labels.
- `image_evidence(claim, probs, map)` — only emits evidence when the model is **confident** (`p ≥ 0.6` or `p ≤ 0.4`); mid-range → nothing → claim stays indeterminate.
- `POST /audit` becomes `multipart/form-data`: `report_text` + `mode` + optional `image`. MIME is sniffed via magic bytes (PNG / JPEG), 10 MB cap, 413 / 415 on violations.
- Legacy JSON callers get `/audit/json`.
- Streamlit file picker + httpx multipart send.

### Phase 5 — Typed claims + extractor protocol
- `ClaimType` enum: OBJECT / ATTRIBUTE / COUNT / SPATIAL.
- `Claim` gains `claim_type`, `count`, `attribute`, `spatial_relation`.
- Extractor classifies each claim based on finding + modifiers.
- `ClaimExtractor` protocol + `RuleBasedExtractor` class — swap in an LLM backend later without touching the graph.

### Phase 6 — Grounding-DINO + bounding boxes
- `models/detector.py` — lazy Grounding-DINO wrapper via `transformers.AutoModelForZeroShotObjectDetection`. Thresholds: `box=0.3`, `text=0.25`. Robust to the `box_threshold` → `threshold` kwarg rename in recent transformers releases.
- `BoundingBox` schema added to `Evidence`.
- `detection_evidence(claim, detections)` emits one evidence item per claim (highest-scoring label match) with bbox + confidence + explicit "experimental, not calibrated disease probability" limitation.
- `node_evidence` runs classifier **and** detector when an image is present; errors are reported in the trace, never swallowed.
- Streamlit draws the X-ray with red bounding boxes via `PIL.ImageDraw`.

### Phase 7 — Fusion & calibration MLP
- `models/calibration.py` — `CalibrationMLP` matching the diagram's **128 → 64 → 3** architecture.
- 8-feature vector per claim: classifier prob, distance from midpoint, detector score, detector-present flag, polarity-negative flag, polarity-uncertain flag, independent-support flag, independent-conflict flag.
- Trained in-process on **2000 deterministic synthetic feature vectors** (seeded; 5 % label noise). Training ~1 s on CPU. Cached via `lru_cache`. No weight file to ship.
- New `node_calibrate` runs between `verify` and `critic`. Every `ClaimVerdict` gains `calibrated_confidence` and `calibrated_probs`.
- The number is calibrated **against the rule verdict, not medical ground truth** — stated in every audit's `verification_method` string and in the UI caption.

### Phase 8 — Risk-aware gate + expert review
- `medical/risk.py` — static clinical-urgency map: `pneumothorax / mass / pneumonia / fracture` = **high**; `atelectasis / emphysema` = **low**; others **medium**.
- `node_human_review` renamed to `risk_gate_human_review`: escalates on blockers, on any `INDETERMINATE`, or when a `high`-risk claim has `calibrated_confidence < 0.75`.
- `api/review.py` — SQLite persistence via stdlib `sqlite3`. Table `review(audit_id, claim_id, decision, note, at)` with upsert. Decisions: `confirm` / `reject` / `insufficient`. DB path overridable via `VISIONGUARD_REVIEW_DB`. `reviews.db` git-ignored.
- `POST /review` + `GET /review?audit_id=…` endpoints.
- Streamlit "Expert Review" tab: lists flagged claims, three one-click buttons per claim, optional note, "Load recorded decisions" button.
- Verdict expanders now show `conf=0.82 risk=high` tags.

### Phase 9 — Audit report v2 + evaluation harness
- `AuditReport.overall_hallucination_status`: one of `clean`, `contradicted`, `needs_review`, `insufficient_evidence`. Derived from per-claim verdicts.
- `medical/evaluation.py` — pure-Python harness. Takes a list of `EvalCase` (report text + expected per-finding status) and an audit callable. Produces per-case results + metrics: accuracy, coverage, abstention rate, precision/recall/F1 per status, confusion matrix, recheck stats, median latency.
- `datasets/eval_fixtures.json` — three bundled synthetic cases.
- `scripts/evaluate.py` — CLI; `--baseline` flag runs the agentic pipeline and the non-agentic baseline side-by-side.
- Honest docstring: metrics measure agreement with the **supplied labels**, not clinical accuracy.

### Phase 10 — VLM under audit
- `models/vlm.py` — `VLMBackend` protocol + `StubVLMBackend` (deterministic canned report). `set_backend(...)` to plug in a real VLM.
- `mode=vlm_from_image` added to `AuditRequest` and `AuditReport`. `AuditReport.input_type` gains `"vlm_generated"`; new `generated_report_text: str | None` field.
- `run_audit` calls the VLM backend when the mode is set, then feeds the generated text through the existing pipeline.
- `/audit` returns 422 if `vlm_from_image` is sent without an image.
- Streamlit shows the generated report text in a code block above the aggregate.
- Plugging in a real VLM is a 5-line integration via `set_backend` — no graph change.

## 7. Core design decisions

### 7.1 Four-tier evidence provenance (T0–T3)
Enforced by `Provenance` enum and the verifier.

| Tier | Meaning | Can it flip a verdict? |
|---|---|---|
| T0 — report text | the source report itself | No (self-agreement is not clinical truth) |
| T1 — extracted claim | structured interpretation of a sentence | No (used as pipeline input, not evidence) |
| T2 — weak label | MeSH / keyword / image-classifier output | Only when **confident** |
| T3 — validated reference | human-adjudicated ground truth | Yes |
| SYNTHETIC | demo-only fixture, always labeled synthetic | Yes (demo only) |
| IMAGE_MODEL | classifier or detector, confident reading | Yes |

### 7.2 Conservative verdict rules
- Missing evidence → `indeterminate`, **never** `contradicted`.
- Report-only agreement → `indeterminate` (T0 alone is insufficient).
- Hedged / uncertain claim → always `indeterminate`.
- Conflicting independent evidence → `indeterminate`.
- Classifier evidence only emitted when `p ≥ 0.6` or `p ≤ 0.4`; mid-range → nothing.
- Detector evidence treated as experimental, with explicit limitation stored on each item.

### 7.3 Honest confidence
`calibrated_confidence` is calibrated against the rule verdict, not clinical ground truth. The verification method string on every audit, the Streamlit caption, and `docs/PROJECT_REPORT.md` all repeat this.

### 7.4 Nothing medical goes out
- No external API calls with medical data (no OpenAI / Anthropic / Google vision).
- No audit persistence beyond the local reviews DB.
- `.gitignore` blocks `.nii.gz`, `.dcm`, PNG under `datasets/**`, `reviews.db`, checkpoints, `.env`, `*.pt`, `*.safetensors`, etc.

### 7.5 Offline-first
- Tests use stubs for every heavy model (`set_backend(...)`); the full 85-test suite runs in ~10 s on CPU with no network.
- Weights download **lazily** on first real inference, cached under `%USERPROFILE%\.cache\{torch,huggingface}\`.
- Synthetic demo mode works with zero downloads.

### 7.6 Pluggable surfaces (ready for upgrade without rewriting)
- `ClaimExtractor` protocol → drop in an LLM-based parser.
- `ClassifierBackend` protocol → swap torchxrayvision for CheXzero / BiomedCLIP.
- `DetectorBackend` protocol → swap Grounding-DINO for MedSAM / BiomedCLIP-detector.
- `VLMBackend` protocol → swap stub for LLaVA-Med / Qwen-VL / BLIP.

## 10. Limitations (be upfront in the report)

1. **Not clinically validated.** Research prototype only.
2. **Rule-based extractor** — misses atypical phrasing, abbreviations, composite findings. LLM slot is wired but not populated.
3. **Image classifier is pretrained, not fine-tuned** — carries biases from NIH / CheXpert / MIMIC-CXR / PadChest / Open-i.
4. **Grounding-DINO is a general-domain zero-shot detector** — will miss subtle chest findings and sometimes box the wrong structure.
5. **Calibrated confidence is calibrated against the rule verdict**, not medical ground truth. Needs a hand-labeled subset of IU X-Ray to become clinically meaningful.
6. **VLM backend is a deterministic stub** — the "generated report" is identical regardless of image until you plug in a real VLM. Protocol slot is open for LLaVA-Med / Qwen-VL / BLIP.
7. **No persistent audit storage** — audits live in the response only; expert reviews are the only persisted artifact.
8. **Fixtures are synthetic.** The 3-case `datasets/eval_fixtures.json` demonstrates the harness; it is not a benchmark.

## 10b. Measured results against hand labels

The author hand-labeled all 42 (claim, image) pairs from `datasets/iu_xray/labeling_queue.json` through the Streamlit "Label Samples" tab. Labels distribution: 31 supported, 11 indeterminate, 0 contradicted.

| Metric | Value |
|---|---:|
| Accuracy (pipeline agrees with annotator) | **78.6 %** (33 / 42) |
| F1 — supported | 0.87 |
| F1 — indeterminate | 0.31 |
| F1 — contradicted | undefined (0 cases in queue) |

**Confusion matrix** (rows = annotator, columns = pipeline):

| | supported | contradicted | indeterminate |
|---|---:|---:|---:|
| supported | 31 | 0 | 0 |
| contradicted | 0 | 0 | 0 |
| indeterminate | 9 | 0 | 2 |

**Observed failure mode — overclaiming on ambiguous images.** When the annotator could not confidently decide ("indeterminate"), the pipeline nevertheless flipped to "supported" 9 of 11 times (82 %). This is a conservative-auditor failure: the system agrees with the VLM-generated claim even when the visual evidence is weak. The 78.6 % headline hides this; it is called out here deliberately.

**Caveats stated for honesty.** Labels come from a non-expert annotator (the project author), not a board-certified radiologist. 42 cases is small (±13 pp 95% CI). The queue happened to contain no cases the annotator judged "contradicted," so the pipeline's actual ability to catch false claims was not measured here — testing that would require deliberately hallucinated reports.
